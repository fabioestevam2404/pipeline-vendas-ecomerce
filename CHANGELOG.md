### Corrigido
- `pd.NA`/`NaN` de campos opcionais não eram reconhecidos pelo pydantic como `None`, causando rejeição indevida de registros válidos com campos opcionais vazios (ex.: pedido sem data de entrega). Corrigido em `src/quality/common.normalize_row`; coberto por teste de regressão.
- `customer_sk` calculada em memória por `build_dim_customers` mudaria a cada execução do pipeline, corrompendo silenciosamente a FK de `fact_pedidos` já persistido. Corrigido: `mart.dim_customers.customer_sk` agora é gerada por `IDENTITY` no banco e nunca sobrescrita em UPSERTs subsequentes; coberto por teste de regressão (`test_customer_sk_e_estavel_entre_cargas_repetidas`).
- Merge entre `dim_tempo` persistida (coluna `date` como `datetime.date` do driver do PostgreSQL) e o DataFrame de itens (`datetime64`) falhava com erro de tipo. Corrigido normalizando o tipo na leitura (`src/loading/load_mart._ler_dim_tempo_persistida`).
- Fan-out potencial (não hipotético — real no dataset): juntar `order_payments`/`order_reviews` (grão de pedido) direto em `fact_pedidos` (grão de item) multiplicaria linhas por número de parcelas/reviews do pedido, inflando receita. Corrigido agregando pagamentos e deduplicando reviews por pedido ANTES do join (`src/loading/dim_pagamento.py`).
- Atribuir uma lista Python com `None` misturado a `int` de volta a uma coluna do pandas sem forçar `dtype=object` faz o pandas reconverter `None` para `NaN` silenciosamente (reinferência de tipo) — isso quebrava a carga de `review_score` nulo no PostgreSQL (`NumericValueOutOfRange`). Corrigido forçando `dtype=object` explicitamente em `build_fact_pedidos`; só foi pego porque o teste de integração roda contra Postgres real, não mock.
- `--start-date`/`--end-date` do script de simulação só filtravam o relatório impresso, não os arquivos de fato escritos em disco — corrigido filtrando `orders_df` antes de particionar.
- Quatro bugs de compatibilidade SQLAlchemy 1.4 (versão que o Airflow 2.9 fixa) vs. 2.0 (versão usada no resto do projeto), todos encontrados rodando o Airflow de verdade, não hipotéticos: (1) `from sqlalchemy import Engine` não existe em 1.4 — corrigido para `from sqlalchemy.engine import Engine`; (2) `CreateSchema(if_not_exists=True)` é ignorado silenciosamente em 1.4, quebrando a idempotência da criação de schema — corrigido com `CREATE SCHEMA IF NOT EXISTS` via SQL bruto; (3) `pd.read_sql(select(...), conn)` quebra na combinação pandas 3.0 + SQLAlchemy 1.4 — corrigido executando o SELECT via `conn.execute()` e montando o DataFrame manualmente.
- Bug próprio na DAG de seed: leitura de `sellers.csv`/`products.csv` via `pd.read_csv()` puro (em vez de `read_csv_file()` do projeto) fazia `seller_zip_code_prefix` ser lido como `int64`, rejeitando silenciosamente todos os registros na validação Pydantic. Corrigido usando `read_csv_file` (dtype=str) consistentemente.
- Efeito colateral da correção acima: `_aggregate_geolocation_by_zip` fazia `.mean()` assumindo `geolocation_lat`/`geolocation_lng` numéricos, quebrando quando o CSV é lido como string. Corrigido convertendo explicitamente com `pd.to_numeric` dentro da própria função, tornando-a robusta ao dtype de entrada.
